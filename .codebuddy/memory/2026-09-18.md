## clipRect 全链路落地（done；"视频内容没锁死在组件内部"的最终修复）

用户报"组件内部的视频内容还是没有完全锁死"——原生帧溢出 overflow:hidden 容器叠在页面上。

**方案＝页面 clipBox（元素盒 ∩ overflow 祖先 padding box ∩ 视口）过桥 → native 按交集裁剪**：
- 协议加第 17-20 字段 clipX/Y/W/H（`page/nmb_protocol.cpp` kFieldClip*，`Media::clipRect`，`setMediaRects` 三参）。
- `render/nmb_composite.cpp` paintBrowser：clip 宽高≤0 或与目标窗口交集为空 → `noclip` diagNote + 整块不画；否则 `IntersectClipRect` 收到交集后照常画完整 rect（帧内容不跳变）。
- 页面：clipBox 裁剪盒精确到 padding box（border 收缩）；`send()` 每条消息带 clip 四字段，`__nmbMedia`（无元素通道）补 4 个 '0'＝完全不可见；syncAll key 加 ckey（容器滚动/伸缩改裁剪能过桥）。

**两个关键教训**：
1. **`send()` 的编辑丢失过一次**：工具报 "succeeded" 但文件里还是旧 17 字段版，导致"页面回读有值、native 恒收全零"。排障口诀：读到矛盾先 grep 现文件确认编辑真在，别只信早前的成功回执。
2. **clip 的权威写入点必须在 syncAll（算 ckey 处），不能放 placeBar**：placeBar 开头 `if(!bar)return`，wrapEl 逐像素保险拆包后永不建条 → 无条元素的 clip 永远缺省 → native 误判"完全不可见"把画面也砍掉。**clip 与条的存亡是两回事**——拆包降级＝无条但有画面。

**拆包机制补充**：video 是 inline 替换元素（垂直 margin 生效），站点给它 margin-top 时 wrapEl 搬到 wrap（div inline 非替换，垂直 margin 无效）→ 位置差 → 保险拆包。合理降级（"布局正确性优先于有控件"），clip 兜底后画面不受影响。

**取证页** `tests/testjs/_nmb_ui_clip.html`（CLIPPROBE 回读 rect+clip 到标题；NMB_PAINT_LOG 看每条目 noclip/drawn 判定）：v1 部分裁剪、v2 双向裁剪（260x120 容器裁 420x240 视频）、v3 完全藏住（`#b3 video{margin-top:150px}` 推出容器 → 交集空 → 不画不显条）。三场景截图全部达标，ui_lock 四档无回归。

## 修"条被钉在窗口最底下 / 悬在残余画面下"（done，已安装；md5 AD77C4946B48A9EC80353C7AC318D820）

用户回报（ui5）：滚动时条始终在"最底下"，往下滚它也在最底下。

**真因（两个叠加）**：
1. `clipBox` 与视口取了交集，我却拿它的结果去**挪条的位置**（`availB=min(r.bottom, box.b)`）。
   元素底边一超出窗口，`box.b` 就被压成视口底边 → 条恒等于 `视口高-38` ＝ **钉死在窗口最下面**，
   正是早先花力气删掉的老毛病，从这里又回来了。
   **结论：裁剪框只能用来判断可见性，绝不能用来挪位置。**位置严格用元素自己的边。
2. 上一版把"被裁即隐藏"的判据写成 `clip = max(r.left-box.l, r.top-box.t, ...)` —— **方向反了**：
   被裁量是 `box.l-r.left`（裁剪框比元素往里收了多少），反过来算恒为负，顶部/左侧裁切
   永远检测不到 → 元素从上方滚出时条照样悬在残余画面下面。

**修法**：位置一律用 `r`（元素自己的边）；被裁量按正确方向算；
加**迟滞**——已显示时容忍 8px 轻裁（滚动中 r 每帧微动，不放余量会在临界点反复显隐＝闪烁），
已隐藏则须基本完整可见才恢复。

元素底边超出视口 → 条不再钉视口底而是隐藏；组件完整可见 → 条贴元素底边(398=196+240-38)；
音频完整可见 → fill 撑满(abar=arect)。

**ui6 的 video opacity:0 已撤回**（ui6 出 bug 的嫌疑源）：video 不再整体隐藏，

## 控件条定位改回 fixed（2026-09-18，用户拍板）

用户明确：**`position:absolute` 不能用**——那样条成了页面滚动内容的一部分，没法"固定"在组件上。

**改法（三处）**：
- `hook/js/injection.js` 的 `placeBar`：删掉 `absolute + 文档坐标（left+sx/top+sy）` 那条路，也删掉 `bar.__nmbFixed`
  的祖先链探测（`buildBar` 里遍历 `getComputedStyle().position==='fixed'` 那段一并删了）；
  现在一律 `position:fixed` + 视口坐标，`left/top/width` 直接写 rect 值。
  **理由（核心口径）**：条与 native 的挖洞/画面要用**同一份 rect、同一拍**更新才能黏在一起；
  用 absolute 时浏览器滚动会立刻把条带走，而画面要等异步 rect（慢 1-2 帧），滚动中必然分家。

## 全屏 fixed 只限最大化态——确认无外泄 + 修陈旧注释（done，已装）

用户报"01-base.css 用太多、脱离原本流；最大化按钮只有最大化态才能用 fixed，其他情况不允许"。

**探针复核 `_nmb_fs_rt.html`（普通/最大化/退出三态 computed position）**：

- 退出态（按钮点击 / 标准 `document.exitFullscreen()` 两条路径都验）：完整回到 `static`+包装盒内，`elRect` 与进全屏前逐像素一致，无内联定位残留。

**结论**：CSS 里 `position:fixed` 只有两条且都由属性门控（`[data-native-media][data-nmb-fs="1"]` 元素、`[data-nmb-controls][data-nmb-fsbar="1"]` 条），普通态条是 `position:absolute` 相对 `position:relative` 的包装盒——本就合规。"退出后仍卡 fixed"只可能是**旧运行时 DLL 没带本会话的 `document.exitFullscreen` defineProperty 修复**（早先修的 bug：内核无该方法 → 退出按钮 TypeError 无反应 → 元素停在 fixed 满视口）。已把修复重建进 `bin/NativeMediaBridge.dll`（REAL-OK 09:26:12）并复测该 DLL 三态全绿。

**顺手修的陈旧注释**：`buildBar` 里一句"条最终挂文档根、走视口绝对定位"是 ui8 旧描述，与现代码（条建在包装盒、仅全屏挪 documentElement）不符，会误导"普通态视口固定"的判断——已改为准确表述。
